# Security Policy

## Supported Versions

As an independent, community-driven project with limited resources, active security maintenance is provided **only for the `main` branch**.

| Version / Branch | Supported |
| :--- | :--- |
| `main` | :white_check_mark: |
| Past releases | :x: |
| Pre-releases | :x: |

### Handling Releases
* Official releases (those not marked as pre-releases) will be published as milestones.
* If a release that is not a pre-release is found to be vulnerable, it will either be **clearly marked with a security warning** or **removed entirely** from GitHub Releases.

## Reporting a Vulnerability

If you discover a security issue or vulnerability:

1. **Open an Issue:** Submit an issue directly in the repository's [Issue Tracker](../../issues).
2. **Details:** Include a concise description of the problem, steps to reproduce, and any affected hardware or build configurations.
3. **Resolution:** Reports will be evaluated and addressed on the `main` branch as maintainer bandwidth allows.
