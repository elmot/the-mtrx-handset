# Contributing to the-mtrx-handset

Thank you for your interest in contributing! Whether you are fixing a bug, adding hardware quirks, or improving documentation, we welcome thoughtful contributions.

## How to Contribute

1. **Check Existing Issues:** Before starting work, look through open issues and discussions to avoid duplicate efforts. For major changes or new features, open an issue first to discuss your approach.
2. **Fork & Branch:** Create a branch with a descriptive name (e.g., `fix/bt-pairing-timeout` or `feat/slint-dialer-screen`).
3. **Verify on Real Targets:**
   * Test your changes against the actual Nokia 8110 4G hardware or a functional Alpine/Slint build environment.
   * Make sure existing builds and scripts run without errors.
4. **Submit a Pull Request:** Open a clear PR explaining what the change accomplishes, why it is needed, and how it was tested.

## Contribution Standards

To keep maintainer overhead manageable and avoid regressions on physical hardware:

* **Substantive Changes Only:** PRs should address concrete bugs, functional improvements, or essential documentation updates. Purely cosmetic rewrites, automated bulk reformatting, or low-utility changes will be closed without review.
* **Testing & Verification:** Whether code is written by hand, with automated tools, or with AI assistance, contributors are personally responsible for verifying that it works properly on hardware.
* **Code of Conduct:** All participation is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).

## Need Help?

If you have questions about device trees, kernel configurations, or flashing workflows, feel free to open a Discussion thread or issue.
